# ЛР № 3. Разработка аналитического дашборда для бизнес-кейса

**Актуальное задание:** [EnvLab № 427](https://envlab.ru/mod/assign/view.php?id=427).  
**Тема:** программные средства аналитики данных. **Максимум — 20 баллов**.  
**Результат:** собственный публичный Git-репозиторий магистранта с полноценным `README.md`, DAG, SQL-витриной и скриншотами дашборда.

## Сквозная архитектура

`Kaggle / открытые данные → Airflow DAG → PostgreSQL RAW → STG → SQL VIEW (витрина) → Apache Superset → бизнес-инсайты`

Не путайте системную БД метаданных Airflow и отдельную аналитическую PostgreSQL. Superset должен работать **с VIEW**, а не напрямую с `stg_*`.

## Обязательные этапы

1. Выберите вариант (1–30) в EnvLab, подтвердите, что исходные столбцы существуют в реальном датасете.
2. Поднимите окружение для DAG, PostgreSQL и Superset; опишите версии и команды воспроизведения.
3. Реализуйте задачи Extract → Load RAW → Transform STG → контроль качества → формирование VIEW. Отслеживайте пропуски и количество записей между слоями.
4. Проверьте корректность показателей SQL и ключевых агрегатов; проанализируйте дубликаты и типы данных.
5. Создайте пять требуемых типов визуализаций, интерактивные фильтры и понятные подписи.
6. Подготовьте `README.md` строго по требованиям EnvLab и сделайте выводы как «наблюдение → объяснение → действие».

### Обновление программной платформы
Архивный пример ориентирован на **Airflow 2.5 + PostgreSQL 12 + Ubuntu 20.04**. Для новой работы рекомендовано использовать поддерживаемые версии ОС, PostgreSQL и Airflow; переход к **Airflow 3.x требует изменения DAG и Docker Compose**, поэтому архивный `docker-compose.yml` нельзя просто «переключить» на другой образ без тестирования. Точные совместимые версии фиксируются и обосновываются студентом.

**Правила безопасности:** не копируйте `lpw_04/kaggle.json`, не публикуйте секреты, не используйте `admin/admin` на доступном извне сервере. Применяйте `.env`/секреты вне Git, ограничивайте порты локальным интерфейсом и не запускайте архивный `cleanup.sh` без проверки: он удаляет неиспользуемые Docker-ресурсы за пределами задания.

**Важно:** в опубликованном HTML-задании EnvLab пока есть ссылки на корневой `lpw_04`. Они сохраняют совместимость со старым примером. При обновлении страницы EnvLab преподаватель может заменить их ссылкой на данный каталог.
